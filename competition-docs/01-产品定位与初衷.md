# 产品定位与初衷

## 1. 产品定位

**CCZU All-knowing 是面向常州大学的校园信息交流 Agent。它依靠信息聚合、用户互动、多层审核，为校园信息交流提供便利和安全保障，打造常州大学专属信息圈。**

它不是泛化的聊天助手，也不是单纯的校园论坛。它将“可检索的校园知识”“全校共享的社区信息源”“可追溯的互动关系”和“受控 Agent 工具链”组合在一起，让用户可以用自然语言提出需求，也可以通过社区机制发布信息、寻找伙伴、讨论细节和私聊确认。

## 2. 制作初衷

### 2.1 校园信息分散

课程、食堂、快递、场馆、活动、二手交易和找搭子信息常散落在多个群聊、朋友圈、公众号和线下通知中。信息量并不一定少，但缺少统一入口和稳定检索方式。

### 2.2 信息随时可能失效

“明晚的球局”“本周的讲座”“假期后的营业时间”都带有时效性。普通搜索结果如果不提示发布时间和有效期，容易让用户把过期信息当成当前事实。

### 2.3 社区内容需要安全边界

校园信息既包含相对稳定的基础知识，也包含大量用户生成内容。若没有审核、权限、状态和确认流程，容易出现虚假信息、恶意内容、重复发布以及越权操作。

### 2.4 通用大模型不了解校内语境

通用模型可以生成流畅文本，但不天然掌握常州大学的食堂、楼宇、场馆和校园生活规则。仅依赖模型记忆会带来幻觉，因此系统必须把回答约束在可检索、可引用的校园数据中。

### 2.5 用户需要“完成任务”，不只是“得到一段话”

用户说“帮我找个学习搭子”时，真正目标是找到可用信息或发出一条待审核需求，而不是只得到建议。因此系统采用 Agent 形态：能检索、匹配、生成草稿、修订草稿和申请缺失目录项，但关键状态变更仍由用户确认。

## 3. 四个核心支点

| 支点 | 产品设计 | 现实作用 |
| --- | --- | --- |
| 信息聚合 | 知识库 + 社区信息源 + 分类目录 | 把稳定知识与实时社区需求放在统一入口 |
| 用户互动 | 公开讨论、私聊、消息中心、未读状态 | 让信息从“看一眼”变成可继续沟通的社区 |
| 多层审核 | 信息源审核、Tag/类型申请审核、知识转存审核 | 控制低质量内容和目录污染 |
| 安全保障 | 权限校验、确认发布、有效期、防注入、防幻觉 | 降低误发布、过期信息和模型编造风险 |

## 4. 目标用户与场景

| 用户 | 主要需求 | 产品能力 |
| --- | --- | --- |
| 普通学生 | 查校园事实、找搭子、二手交易、失物招领、校园经验 | Agent 检索、信息源发布、公开讨论、私聊、消息提醒 |
| 信息发布者 | 发布活动、招募、交易或求助，并持续沟通 | AI 辅助分类、有效期、讨论开关、草稿与审核状态 |
| 管理员 | 审核内容、维护目录、维护知识、观察用户 | 审核后台、知识库、Tag/类型管理、用户监控 |

典型场景包括：

- “学校里有哪些运动场地？”
- “明晚 20:00 想找人去图书馆学习。”
- “求购一辆二手自行车。”
- “捡到一张校园卡，怎么发布失物招领？”
- “学校周边有哪些适合聚餐的店？”
- “我刚才的草稿少写了一个人，帮我更正。”

## 5. 产品不是什么

- 不是只有问答的 Chatbot。Agent 会根据意图进入检索、草稿或修订工具链。
- 不是让大模型直接写数据库。所有数据库写入都进入受控 API，并经过权限与状态校验。
- 不是无审核的匿名墙。信息源、目录申请和知识转存都有管理员参与。
- 不是实时官方系统。平台提供信息聚合和社区协作，但用户仍需对联系、交易和线下活动自行核实。
- 不是替代 RAG 的通用方案。它针对结构化、强约束、规模可控的校园信息场景选择了更可解释的混合检索路线。

## 6. 产品价值

### 对学生

- 用自然语言直接表达需求，不需要学习复杂筛选语法。
- 同时看到知识库依据和社区信息，知道答案从哪里来。
- 通过讨论和私聊继续确认时间、地点、人数和联系方式。
- 过期、无结果和模型失败时都有明确提示，不把“没有找到”伪装成“已经找到”。

### 对校园社区

- 信息源形成全校共享的社区广场，知识库沉淀稳定内容。
- Tag 和类型由社区提出、管理员审核，目录可以随校园需求增长。
- 公开讨论适合确认活动安排，私聊适合交换不适合公开的细节。

### 对管理员

- 审核状态、目录申请、用户活跃度和知识来源集中可见。
- 关键操作有明确状态和确认流程，降低误操作。
- 可以通过用户监控识别账号活跃情况，并维护平台秩序。

## 7. 展示时的核心叙事

建议用以下顺序介绍：

1. **问题**：校园信息分散、过期、真假难辨，通用大模型又不懂校内语境。
2. **方案**：用一个校园 Agent 聚合知识和社区信息，同时保留互动与审核。
3. **差异**：不是“模型自由发挥”，而是“结构化检索 + 受控工具调用 + 多层审核”。
4. **效果**：用户能搜索、发布、修订、讨论和私聊；管理员能审核、维护和监控。
5. **安全**：硬性条件、阈值重试、过期降权、防幻觉 Prompt 和权限校验共同兜底。

## 8. 产品边界与后续方向

当前系统聚焦常州大学西太湖校区的校园信息交流，不承诺替代学校官方通知系统。涉及人身安全的内容会优先提示急救或校园保卫渠道。

后续可扩展方向包括：

- 引入向量检索，与现有结构化检索形成混合召回。
- 增加消息推送、举报处置和数据统计看板。
- 对接学校官方场馆、食堂和活动数据源。
- 增加更细粒度的审核日志和内容治理策略。
