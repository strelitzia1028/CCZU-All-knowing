## 一句话定位

**CCZU All-knowing 是面向常州大学的校园信息交流 Agent。它依靠信息聚合、用户互动、多层审核，为校园信息交流提供便利和安全保障，打造常州大学专属信息圈。**

## 60 秒介绍

校园信息通常散落在群聊、朋友圈、表白墙和线下通知中，存在三个问题：信息找不到、内容容易过期、真实性和安全性缺少保障。

CCZU All-knowing 将“知识库 + 社区信息源”聚合到一个平台中。用户既能向 Agent 提问，也能发布找搭子、二手交易、失物招领、校园经验等信息，并通过公开讨论或私聊继续沟通。

平台不是让大模型直接操作数据库，而是采用受控 Agent 工具链：先理解需求，再进行检索、匹配、草稿生成或修订；发布和审核必须由用户及管理员确认。系统还通过多层审核、有效期管理、过期降权、标签分权检索和防幻觉 Prompt，兼顾便利性与安全。

## 建议演示路线

1. 以普通用户登录，向 Agent 提出“明晚找图书馆学习搭子”的需求。
2. 展示需求总结、工具调用轨迹、知识库结果和社区信息源结果。
3. 展示无匹配结果时的兜底提示，以及 Agent 生成的待确认草稿。
4. 展示草稿修订、Tag/类型 AI 推荐、用户确认后提交审核。
5. 切换信息源、知识库和消息页面，展示筛选、卡片、公开讨论、私聊和未读提示。
6. 以管理员登录，展示审核后台、知识库维护、Tag/类型管理、用户监控和账号安全。

## 技术概览

- 前端：Next.js 16、React 19、TypeScript、Tailwind CSS
- 后端：Express 5、TypeScript
- 数据库：PostgreSQL 15、Drizzle ORM
- AI：智谱 GLM-4-Flash，OpenAI 兼容接口
- 部署：阿里云 ECS、Nginx、systemd

## 展示重点

- **不是普通聊天机器人**：Agent 会调用受控工具改变任务路线，但不会自动发布或审核。
- **不是纯 RAG**：在结构化校园短信息场景中，采用 SQL 粗筛 + Tag/关键词/实体分权排序，更可控、可解释。
- **不是单点审核**：信息源、Tag 申请、类型申请、知识转存和管理操作形成多层治理。
- **不是盲目扩 Tag**：Agent 先读取已有 Tag 名称与描述，新增候选需通过完整词形、已有覆盖和 AI 必要性复审，每份草稿最多新增 1 个。
- **不是只追求召回**：同时处理硬性时间/地点/人数约束、过期内容、无结果、模型失效和重试策略。
- **不是只展示回答**：工具调用过程、知识依据、社区卡片、草稿状态和互动消息都在界面中可见。
- **双层回答隔离事实与推理**：严格依据回答独立展示；AI 推理补充可读取知识库正文、组合社区广域素材，并在路线与周边场景中追加带来源的网络检索。网络结果不会进入严格回答，第二层默认折叠、标注未验证，并过滤素材外具体实体。
